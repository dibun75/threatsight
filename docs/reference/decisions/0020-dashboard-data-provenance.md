# ADR 0020 — Dashboard data provenance transparency

**Status:** Accepted  
**Date:** 2026-08-27

## Context

M10.1 must make executive dashboard counts honest about where they come from. Reviewers can otherwise read synthetic demo inventory, seeded controls, or CTRL-002 findings as live enterprise discovery or legal compliance.

## Decision

- Derive provenance from existing persisted records. Do not add engines, scanners, or new control families.
- Show **data origin**, **evidence source**, **generated by**, and **last updated** on major dashboard metrics.
- Label synthetic demo inventory and manual registration distinctly. Discovery remains authorized labelled-demo fetch only.
- Keep the deterministic assurance status model. Never emit `COMPLIANT`. Never claim legal compliance.

## Consequences

- Empty environments still show zeros, now with `No records yet` origins.
- Showcase copy can state that ThreatSight unifies registered systems, governance records, evidence, and deterministic tests.
- M10.1 is a transparency increment, not a capability milestone.
